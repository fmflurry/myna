A \\?\ path made model download throw

The Windows app starts download-models.ps1 from a canonicalized resource path. PowerShell Join-Path then reports that the drive argument is null, before any model is fetched. A short first Qwen shard was also treated as a finished download.

Bug path 1

Join-Path cannot read a verbatim drive.

1. App starts the script 2. Join-Path drive is null

Rust canonicalize and Tauri’s resource directory use \\?\. dunce drops a safe disk prefix; \\?\UNC\ is stripped in the same helper. The script strips both again before $PSScriptRoot, -Dest, or MYNA_MODELS_DIR reach Join-Path.

Bug path 2

One shard file is not a finished Qwen download.

1. App starts the script 2. Path is a normal drive or UNC path 3. Used to skip

Same rule in download-models.sh. -Check already listed both shards; it still does. Part 2’s floor is the Hugging Face size, 689,872,288 bytes.

If curl.exe is missing

$ProgressPreference is SilentlyContinue so Invoke-WebRequest does not redraw a progress bar per packet. Download-File uses curl with --retry 3, throws when curl exits non-zero, and falls back to Invoke-WebRequest. Every fetch goes through that function.
