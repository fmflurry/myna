# Releasing on macOS

This describes `scripts/release-macos.sh`: build, sign, verify, and
(optionally) notarize the macOS release bundle.

## Why this exists

macOS ties TCC permission grants (microphone / `kTCCServiceAudioCapture`) to
an app's **Designated Requirement (DR)**, not to its bundle ID or path. Per
Apple TN3127: *"macOS records an app's DR in its database of apps authorized
to access privacy-protected resources… Each time the app accesses the
resource, macOS checks that the current version satisfies the original DR."*

Ad-hoc signing (no certificate, `signingIdentity: "-"`) produces a DR that is
a bare `cdhash` — the hash of that exact build. Every rebuild is "different
code" as far as the DR is concerned, so the microphone grant silently dies
on the next build. Worse, System Settings still shows the toggle **ON**,
with no way to re-prompt the user.

Signing with *any* certificate — even one that isn't yet trusted by Apple —
gives the DR a stable anchor: it can name the certificate instead of a
per-build hash. Certificate **trust** is irrelevant to DR *evaluation*
(only an explicit `anchor trusted` clause in the requirement consults trust
settings), so a self-issued Apple Development cert is enough to get a stable
DR for local/internal builds.

The catch: codesign's *default* DR for a certificate-signed app pins
`leaf[subject.CN]` (the certificate's Common Name), whose value can change
when the certificate is renewed. So this script pins the DR explicitly to
`leaf[subject.OU]` (the Apple Developer **Team ID**, which does not change)
— see `app/src-tauri/Myna.requirements`. TN3127 warns that default DRs
across identity types are *"not mutually compatible"*, and changing a DR
after grants exist puts users in an unrecoverable silent-denial state.

**Once a signed build has shipped, the DR expression in
`app/src-tauri/Myna.requirements` must never change.**

## One-time setup: get a signing certificate

1. Open Xcode → **Settings** → **Accounts**.
2. Select your Apple ID (add it if not already present).
3. Click **Manage Certificates…**.
4. Click **+** → **Apple Development**.
5. Xcode creates the certificate and installs it (with its private key) in
   your login keychain.

Find your Team ID (needed below) via Xcode's Accounts pane, or:

```bash
security find-identity -v -p codesigning
# "Apple Development: Your Name (ABCDE12345)" — ABCDE12345 is the Team ID
```

## One-time setup: get an updater signing key

The Tauri updater plugin signs every release artifact with a
[minisign](https://jedisct1.github.io/minisign/) key pair, independent of
Apple code signing. Generate one once:

```bash
npx tauri signer generate -w ~/.tauri/myna-updater.key
```

This writes the **private** key to `~/.tauri/myna-updater.key` and prints
the **public** key to stdout. The public key already lives in
`app/src-tauri/tauri.conf.json` (`plugins.updater.pubkey`); you only need to
re-run `generate` (and update that field) if you're rotating the key.

- The private key **must** live under `~/.tauri/` (or another path outside
  the repo) — **never commit it**. `scripts/release-macos.sh` reads it via
  the `TAURI_SIGNING_PRIVATE_KEY` env var (a path or the raw key content
  both work).
- **Losing this private key strands every existing install.** The updater
  only trusts artifacts signed by the key matching the pinned `pubkey` in
  `tauri.conf.json`. If the private key is lost, the only recovery is
  generating a new pair and shipping a new `pubkey` — but installed copies
  already validate against the *old* pubkey and have no way to fetch an
  update signed with a key they don't trust. Every existing user is
  stranded on their current version and must manually re-download and
  reinstall. Back this key up somewhere durable and access-controlled
  (a password manager or secrets vault), the same way you'd treat a
  code-signing certificate's private key.
- The current key (`B3CC8CB79070B452`) was generated **without** a password,
  so only `TAURI_SIGNING_PRIVATE_KEY` needs provisioning (in CI and locally).
  `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` is not used — leave it unset, or set
  it to an empty string; either is handled by `scripts/release-macos.sh`.

## Environment variables

| Variable | Required for | Purpose |
| --- | --- | --- |
| `APPLE_SIGNING_IDENTITY` | Optional | Explicit codesign identity (name or hash). If unset, the script auto-detects the sole installed codesigning identity, or falls back to ad-hoc (`-`). |
| `APPLE_TEAM_ID` | Required when signing with a real identity | Your Apple Developer Team ID. Baked into the pinned DR — never hardcode this in the repo (it's public). |
| `APPLE_ID` | Notarization only | Apple ID used to submit for notarization. |
| `APPLE_PASSWORD` | Notarization only | App-specific password for `APPLE_ID` (not your Apple ID password). |
| `TAURI_SIGNING_PRIVATE_KEY` | Required (updater artifacts) | Path to, or content of, the minisign private key generated by `tauri signer generate` (see below). `bundle.createUpdaterArtifacts: true` in `tauri.conf.json` means the script fails loudly if this is unset. |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Required if the key has a password | Password for `TAURI_SIGNING_PRIVATE_KEY`. Set to an empty string if the key was generated without one. |

Notarization runs only when `APPLE_ID`, `APPLE_PASSWORD`, and
`APPLE_TEAM_ID` are **all** set; otherwise it is skipped with a one-line
notice, and the script still exits 0.

## Running it

```bash
# Ad-hoc (no cert installed, or you want an unsigned dev build):
scripts/release-macos.sh

# Signed, auto-detected identity (works only if exactly one is installed):
APPLE_TEAM_ID=ABCDE12345 scripts/release-macos.sh

# Signed, explicit identity + notarization:
APPLE_SIGNING_IDENTITY="Apple Development: Your Name (ABCDE12345)" \
APPLE_TEAM_ID=ABCDE12345 \
APPLE_ID=you@example.com \
APPLE_PASSWORD=app-specific-password \
scripts/release-macos.sh
```

## What it does

1. Deletes stale `target/release/myna` and `target/release/bundle` — a
   cached binary once let a broken link step pass silently.
2. Resolves the signing identity (env var → sole installed identity →
   ad-hoc, with a loud warning in the ad-hoc case).
3. If signing for real: renders `app/src-tauri/Myna.requirements` (a
   template with an `__APPLE_TEAM_ID__` placeholder) into a concrete DR
   using `APPLE_TEAM_ID`.
4. Runs `tauri build --bundles app,dmg`, which builds and does an initial
   sign of the `.app` and packages a `.dmg`.
5. If signing for real: re-signs the `.app` with `--requirements` pinned to
   the explicit DR and `--options runtime`, then **rebuilds the dmg from
   that re-signed app** (reusing tauri's generated `bundle_dmg.sh`) —
   never the other way around, or the shipped dmg would carry the old
   signature.
6. Verifies the `.app`: `codesign -dv --verbose=2` (sealed resources v2,
   bound Info.plist), `codesign --verify --deep --strict`, and
   `codesign -d -r-` — asserting the DR contains a `certificate` clause
   (not a bare `cdhash`) when signed for real. Runs `spctl -a -t exec -vv`
   and treats `rejected` (unnotarized-but-assessable) as expected; only a
   *resource* error fails the build.
7. **Mounts the built dmg and re-verifies the app inside it** — the
   artifact users actually receive, not just the pre-bundling copy.
8. Verifies the updater artifact (`Myna.app.tar.gz` + `.sig`, produced by
   `tauri build` since `createUpdaterArtifacts: true`): if signing for real,
   the tarball tauri built came from the *pre-re-sign* app, so the script
   **regenerates it from the re-signed `.app` and re-signs it** with
   `tauri signer sign` — otherwise the shipped updater artifact's signature
   would validate an app that isn't the one in the dmg. Then extracts the
   final tarball and re-runs `codesign --verify --deep --strict` on it.
9. Notarizes and staples only when fully configured; otherwise skips with a
   notice.
10. Prints a summary: identity used, DR, artifact paths/sizes, and whether
    the updater artifact is minisign-signed.

`scripts/make-latest-json.sh` runs separately, after `release-macos.sh`
succeeds (see [CI: tag-triggered releases](#ci-tag-triggered-releases)): it
reads the version from `tauri.conf.json` and the signature from
`Myna.app.tar.gz.sig` to emit `latest.json`, and fails if the tag being
released doesn't match that version.

## After switching signing identity: reset TCC grants

Switching signing identity (ad-hoc → certificate, or between certificates)
changes the DR, which invalidates any existing microphone grant for
`app.myna.desktop`. Before first launching a newly-identity-signed build:

```bash
sudo tccutil reset All app.myna.desktop
```

Otherwise the app is silently denied microphone access with no prompt, and
it will look like a regression rather than an expected consequence of
re-signing.

### In-place updates behave the same as the DMG path

The updater's in-place install ([ADR 0012](adr/0012-user-initiated-in-app-update.md))
replaces the running bundle with a build carrying a *new* ad-hoc `cdhash`, so
it resets the microphone and audio-capture (Screen & System Audio Recording)
grants **identically** to installing the freshly-signed DMG by hand. There is
no difference to TCC between "drag the new DMG over the old app" and "click
Update in-app" while builds are ad-hoc signed — both change the DR, both drop
the grant. This is why ADR 0012 shows an explicit re-prompt caveat before the
update restarts the app: the consequence is unavoidable under ad-hoc signing,
so it is surfaced rather than hidden.

**Developer ID signing fixes this with zero code change.** Once releases are
signed with a stable Team ID and the DR is pinned to `leaf[subject.OU]` (see
above), every build satisfies the same Designated Requirement, so the grant
survives both the DMG path and the in-place updater. The caveat simply stops
firing; no update-flow code needs to change.

## CI: tag-triggered releases

`.github/workflows/release.yml` runs `scripts/release-macos.sh` on
`macos-14` (Apple Silicon — required for the macOS 14.4+ Core Audio
process-tap APIs) whenever a `v*` tag is pushed, then runs
`scripts/make-latest-json.sh`, then uploads the `.dmg`, `Myna.app.tar.gz`,
`Myna.app.tar.gz.sig`, and `latest.json` to a GitHub Release via
`softprops/action-gh-release`. It requires `permissions: contents: write`
(already set in the workflow) so the release job can create the Release and
attach the assets.

`APPLE_*` signing/notarization secrets are **optional**. When none are
configured, the workflow still completes and publishes an **ad-hoc signed**
dmg — with a loud `::warning::` annotation on the run, since ad-hoc TCC
grants (see above) won't survive the *next* release. `TAURI_SIGNING_*`
secrets are **not optional**: `bundle.createUpdaterArtifacts: true` means
`scripts/release-macos.sh` fails the whole run rather than publish an
unsigned updater artifact.

### Secrets to provision (Settings → Secrets and variables → Actions)

| Secret | Required for | Purpose |
| --- | --- | --- |
| `APPLE_CERTIFICATE` | Signed builds | Base64-encoded `.p12` export of your Developer ID Application certificate (including private key). Export from Keychain Access: right-click the certificate → **Export…** → `.p12`, then `base64 -i cert.p12 \| pbcopy`. |
| `APPLE_CERTIFICATE_PASSWORD` | Signed builds | The password you set when exporting the `.p12`. |
| `APPLE_SIGNING_IDENTITY` | Optional | Explicit codesign identity (name or SHA-1 hash), same as the local env var above. If unset, `security find-identity -v -p codesigning` auto-detects the identity imported from `APPLE_CERTIFICATE`. |
| `APPLE_TEAM_ID` | Signed builds | Your Apple Developer Team ID — baked into the pinned Designated Requirement. Not secret in the sense of being sensitive, but stored as a secret for convenience; safe to treat as a repo variable instead if preferred. |
| `APPLE_ID` | Notarization | Apple ID used to submit for notarization. |
| `APPLE_PASSWORD` | Notarization | App-specific password for `APPLE_ID` (generate at appleid.apple.com, not your Apple ID password). |
| `TAURI_SIGNING_PRIVATE_KEY` | Required (updater) | Content of the minisign private key from [`tauri signer generate`](#one-time-setup-get-an-updater-signing-key) (paste the file contents, not a path — there's no repo-local file for CI to reference). |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Required if the key has a password | Password for `TAURI_SIGNING_PRIVATE_KEY`. Set to an empty string as the secret value if the key was generated without one. |

**Losing `TAURI_SIGNING_PRIVATE_KEY` strands every existing install** — see
the warning in [One-time setup: get an updater signing key](#one-time-setup-get-an-updater-signing-key).
Store a backup of this secret outside GitHub before rotating or deleting it
here.

The workflow imports `APPLE_CERTIFICATE` into a throwaway keychain scoped to
the runner (`$RUNNER_TEMP/app-signing.keychain-db`, destroyed with the
runner at job end) before invoking `scripts/release-macos.sh`, which then
finds the imported identity exactly as it would a locally-installed one.

### Cutting a release

```bash
git tag v0.1.0
git push origin v0.1.0
```

The workflow builds from that tag's commit; it does not bump
`app/src-tauri/tauri.conf.json` or any `Cargo.toml` version for you — bump
and commit those first if the release should carry a new version number.
